
Sequentially Spent Score (SSS) — checking electowiki's claims and one engine bug.

Sources under test:
  * https://electowiki.org/wiki/Sequentially_Spent_Score  (fetched 2026-08-02 via action=raw)
  * https://electowiki.org/wiki/Vote_unitarity            (same)
  * BUG_sss_verbosity.md / larryhastings/starvote#17, via the vendored fork in
    masiarek/star-voting-library

Pure Python, no dependencies. Exact rational arithmetic throughout (Fraction), so
every printed total is the real number and not a float artefact — the electowiki
page prints rounded intermediates and two of them are wrong, which only shows up
if you keep the fractions.

WHAT THIS SCRIPT CAN AND CANNOT ESTABLISH
-----------------------------------------
  * A FAILURE is a finite witness and is exact.
  * A SATISFACTION is only "no counterexample in the window searched"; windows are
    stated per check.
  * Checks 5-7 sample random profiles with a fixed seed, so they are reproducible
    but not exhaustive.

THE METHOD (scaling variant, from the page's own reference implementation)
--------------------------------------------------------------------------
  quota = V / W                       (on ballots normalised to [0,1])
  repeat W times:
      w  = argmax over remaining candidates of  sum_i  s[i][c] * weight[i]
      surplus_factor = max(total[w] / quota, 1)
      spent[i]  = s[i][w] * weight[i] / surplus_factor
      weight[i] = clip(weight[i] - spent[i], 0, 1)

==============================================================================
  21 ballots: a 13-voter majority bloc (Alice/Ben/Cara) and an 8-voter

    Bloc Score               -> ['Alice', 'Ben', 'Cara']

    reweighting-removed SSS == Bloc Score: True
    minority bloc represented, with reweighting:    True
    minority bloc represented, without reweighting: False

  These are the exact winner sets the bug report records for verbosity=0
  and verbosity>=1. The engine was not mis-tabulating SSS; at verbosity=0
  it was running a DIFFERENT METHOD -- the non-proportional one.

  RESULT: PASS

CHECK 4 — the surplus-handling centrist bias ('only Bs are elected')
==============================================================================
  102 voters, 5 seats, three blocs 41 / 20 / 41. The page states, under
  'Sorted Surplus Handling Variant', that here 'only Bs are elected'.

  proportional entitlement at 5 seats: A 2.01   B 0.98   C 2.01

    scaling : ['B1', 'B2', 'B3', 'A1', 'C1']
              by bloc ['B', 'B', 'B', 'A', 'C'] — B takes 3/5, 'only Bs' = False
    capping : ['B1', 'B2', 'B3', 'B4', 'B5']
              by bloc ['B', 'B', 'B', 'B', 'B'] — B takes 5/5, 'only Bs' = True

  The claim holds for the CAPPING variant and not for the SCALING one —
  and scaling is the current method; the same page says capping 'was
  abandoned'. So the example is inherited from the superseded variant.

  The bias it illustrates is real either way: the 20% centre bloc is owed
  0.98 seats and takes 3 under the current method — about 3x
  over-representation, not 5x. Both 41% wings are owed 2.01 and get 1 each.
  The strategic incentive the page draws from it (wings truncate B to 0)
  survives at the smaller magnitude.

  RESULT: PASS — claim reproduces only under capping.

CHECK 7 — the Vote Unitarity axioms VU1 and VU2, as stated on the wiki
==============================================================================
  3,000 random 6-voter, 4-candidate, 2-seat profiles, exact arithmetic.

    VU1 (proportionate spending, p[i][c] <= s[i][c]) violations: 0
    VU2 (residual budget == 1 - sum of payments)   violations: 0
    profiles where the weight clip at 0 was load-bearing:       0

  RESULT: PASS — SSS satisfies its own axioms exactly,
          and the clip in the reference implementation never binds: spending is
          s[i][w]*weight[i]/surplus <= weight[i] because s <= 1 and surplus >= 1.
          Note the wiki's VU2 remark that 'no rule using multiplicative
          reweighting can satisfy this condition' is about the BUDGET being
          additive; SSS scales the ballot multiplicatively and tracks the budget
          additively, which is why it passes.
